# thinking_effort 参数 + 思考内容呈现

遵循既有分层：类型 → provider → 循环/事件 → TUI → 配置/CLI → 测试。思考内容只走事件流不进 State（wire 协议禁止把 reasoning 回传，且恢复会话不需要它）——符合"State 只记录恢复所必须的数据"。

## 1. 类型（src/types.ts）

- `StreamChunk` 增加 `{ kind: 'thinking'; delta: string }`（位于 text 之前到达）
- `ModelResponse` 同步增加 `{ kind: 'thinking'; content: string }`（ScriptedProvider 测试用）

## 2. Provider（src/provider/openai.ts）

- `OpenAIProviderOptions` 增加 `thinkingEffort?: string`；构造后非空则在请求体加 `body['thinking_effort'] = <值>`（字段名按用户端点约定，值透传如 low/medium/high）
- SSE 解析：`delta.reasoning_content`（DeepSeek-R1 风格，主流网关通用）为主，`delta.reasoning`（OpenRouter 风格）为别名，命中即 yield `{ kind: 'thinking', delta }`
- 非 SSE JSON 回退路径：`message.reasoning_content` 产出单个 thinking chunk
- 只有 thinking 没有 text/tool_calls 的响应仍按"空响应"报错

## 3. 循环与事件（src/agent/events.ts + loop.ts）

- 新 Domain 事件 `{ kind: 'assistant_thinking'; content: string }`——与 assistant_text 一致携带累积全文，TUI 零累积逻辑
- `think()` 累积 thinking 并发事件；**不写入 State/messages**（注释说明：reasoning 不可回传、恢复不需要）

## 4. TUI（src/tui/index.ts）

- theme 增加 `thinking`（暗色+斜体 ANSI `2;3`，wrapTextWithAnsi 已确认跨行保持样式）
- 首个 thinking delta 到达时：transcript 加 `✻ thinking` 暗色标签行 + 流式暗斜体文本块，loader 切为 `reasoning…`
- 每轮重置引用（model_request / 新提交），已渲染的思考块保留在 transcript 中供回看

## 5. 配置与 CLI（src/config.ts + cli.ts）

- `Config.thinkingEffort?: string`，优先级 CLI `--thinking-effort` > env `MORTIS_THINKING_EFFORT` > 配置文件 > 不发送
- 随 ensureFileConfig 持久化（非敏感）；usage 增加说明行；provider 构造直接吃 config（结构兼容）

## 6. 测试

- provider：SSE reasoning_content 增量 → thinking chunks；`reasoning` 字段别名；body 含/不含 `thinking_effort`；非 SSE reasoning_content
- agent：ScriptedProvider 发 thinking → 累积 `assistant_thinking` 事件；snapshot.messages **不含** thinking
- tui：assistant_thinking 渲染出标签与暗斜体内容
- config：thinkingEffort 三级优先级
