# Mortis 四层架构改造（修订版：钉死 14 个语义点）

实施顺序 A→B→C→D，每阶段独立可验证。六条核心不变量贯穿实现并写入 AGENTS.md / .agents/CONTEXT.md：
1. State 是普通、可序列化的数据；2. Reducer 是唯一的 State mutation authority；3. Decision 只描述意图，不执行副作用；4. Effect 可并发，transition 串行且 deterministic；5. Scope 拥有 Effect 生命周期，Run 结束必须清理；6. Agent Core 不知道 TUI、Persistence、具体 Runtime。

## 阶段 A：State（含 status）+ Reducer（具体事件，内建 interrupt 转移）

**新增 `src/agent/state.ts`**
```ts
export type AgentStatus = 'idle' | 'running' | 'awaiting_user' | 'done'
export interface AgentState {
  readonly messages: readonly Message[]
  readonly status: AgentStatus
}
export type StateEvent =
  | { type: 'user_message'; content: string }                              // → running
  | { type: 'assistant_message'; content: string | null; toolCalls?: ToolCall[] } // 纯文本→done；带 calls→running
  | { type: 'tool_result'; toolCallId: string; content: string }
  | { type: 'tool_error'; toolCallId: string; content: string }            // effect 级失败，独立提交
  | { type: 'run_interrupted'; reason: string }                            // → idle，reducer 内部补齐悬空 tool 结果
  | { type: 'awaiting_user'; reason: string }
```
- `reduce(state, event)` 纯函数；status 从事件派生（不引入 currentTool/currentTurn 等瞬时字段）
- `run_interrupted` 是正式转移：reducer 为悬空 tool_calls 追加 `"(interrupted: reason)"` 合成结果，保证 **status ≠ 'running' 的状态永远可直接发送**（tool-call invariant）
- 禁止万能事件（string type + unknown payload），TS 判别联合保证穷尽

**重构 `src/agent/loop.ts`**：`run()` 拆 `think()`（消费流 → Decision）与 `act()`（执行 Effect），所有状态变化只经 `reduce`；maxTurns 耗尽时经 run_interrupted 转移后抛错，state 对下一轮有效。

**测试 `test/state.test.ts`**：每类事件单元断言 + **不变量测试**：seeded PRNG 生成随机合法事件序列（~200 步），每步断言 (a) status ∈ 合法集 (b) status ≠ running 时 tool-call pairing 成立 (c) structuredClone 可序列化。

## 阶段 B：Decision/Effect 抽象 + Scope 层次 + 分层取消语义

**`src/types.ts` 扩展**
```ts
export type Effect = { kind: 'tool_call'; call: ToolCall }   // 未来: sub_agent / permission / sleep
export type Decision =
  | { type: 'respond'; content: string }    // 中间文本，循环继续
  | { type: 'execute'; effects: Effect[] }
  | { type: 'wait'; reason: string }        // → awaiting_user
  | { type: 'finish'; result: string }      // → done
```
think() 做映射：纯文本 → finish；tool_calls → execute（ Decision ≠ 模型原始输出）。

**新增 `src/agent/scope.ts`：父链 Scope（Process > Agent > Run > Effect 四层，代码先落三层）**
```ts
export class Scope {
  fork(): Scope            // 子 scope；父 abort 传播到所有后代
  get signal(): AbortSignal
  abort(reason?: string): void
  dispose(): void          // 生命周期结束，从父链摘除
}
```
Agent 构造时建 AgentScope；run() fork 出 RunScope（finally dispose）；每个 Effect 执行 fork 出 EffectScope（执行完 dispose，未来 per-effect cancel 即保留 handle）。

**契约扩展（可选参数，向后兼容）**：`completeStream(messages, tools, signal?)`；`Tool.execute(args, ctx?: { signal })`；provider 把 signal 传 fetch 并在 SSE 循环 throwIfAborted；bash 传给 execFile（Node 原生 kill 子进程）。

**取消语义按层映射（每层只认识相邻术语）**：provider/tool 层只见原生 AbortError → agent 层捕获后 reduce `run_interrupted` 并抛 `RunInterruptedError` → TUI 捕获后显示暗色"(已中断)"。`agent.abort()` 中止当前 RunScope；TUI Ctrl+C：运行中→中断本轮（保留会话），空闲→退出；/q、Ctrl+D 不变。

**Domain/UI 事件分层**：`src/agent/events.ts` 只留 Domain 事件（model_request / assistant_text / tool_start{toolCallId} / tool_result{toolCallId, content, isError} / run_interrupted{reason}）。tool_result 携带完整内容与 isError；**显示截断职责移回 TUI**（UI 关注点），spinner 文案、✓、markdown 渲染全部由 AgentTui 从 domain 事件派生。

## 阶段 C：并发执行 + 有序提交（deterministic）+ allSettled

act()：
```ts
const settled = await Promise.allSettled(effects.map((e) => this.runEffect(e, runScope)))
for (let i = 0; i < effects.length; i++) {
  // 按声明顺序提交：fulfilled → tool_result；rejected → tool_error
  // 单个 Effect 失败不影响其他 Effect 的结果提交
  this.state = reduce(this.state, event); /* 同序 emit domain 事件 */
}
```
- 执行并发、提交有序（A→B→C），session replay / snapshot / 测试不受真实完成时序影响
- tool_start 在执行开始时 emit（实时）；tool_result/tool_error 在提交时按序 emit
- TUI 行追踪改 `Map<toolCallId, Text>`；✓ 标记按提交顺序出现

**测试**：3 个 tool_calls（第 2 个失败/慢）→ 三条结果按声明顺序提交（2 result + 1 error）；TUI 交错 id 行各自打 ✓。

## 阶段 D：版本化 SessionSnapshot + transition 级 checkpoint

**新增 `src/session.ts`**
```ts
export interface SessionSnapshot { version: 1; model: string; messages: Message[]; savedAt: string }
serializeState(state, model): SessionSnapshot
hydrateState(snapshot): AgentState | null   // 校验+迁移；version≠1 → null；status 一律重置为 idle
```
- 落盘 `~/.mortis/sessions/<ts>.json`；`latestSession()` 跳过损坏/未知版本文件
- **checkpoint 挂 transition 不挂 run**：`AgentOptions.onTransition?: (state) => void` 在每次 reduce 后触发（纯观察，loop 不感知 persistence）；CLI/TUI 注册 checkpoint → serialize + 写盘。中途 crash 只丢最后一个未完成 transition
- CLI：`--continue` 用 hydrate 的 state 构造 Agent（`AgentOptions.state?`），TUI header 标 "(resumed)"

**测试**：roundtrip、version 2 文件 → null、--continue 后 ScriptedProvider 可见历史消息。
